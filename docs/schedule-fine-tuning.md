## Schedule Parsing Guide

학교별 강의시간 문자열 파서를 수정하거나 확장할 때 참고하는 작업 기준 문서다.
목표는 학교마다 다른 원문 포맷을 가능한 범위에서 구조화하되, 애매한 입력 때문에 잘못된 시간을 만들어내지 않는 것이다.

### 목적

- `lecture_time_raw`에 들어오는 학교별 강의시간 문자열을 분석해 `meeting_slots`로 구조화할 때 참고한다.
- 파서 개선 시 어떤 케이스를 지원해야 하는지, 어떤 경우에 보수적으로 처리해야 하는지 정한다.
- 새 패턴을 추가할 때 회귀를 줄이기 위한 테스트 기준을 함께 제공한다.

### 공통 출력 원칙

- 원본 문자열은 항상 `lecture_time_raw`에 보존한다.
- 확실하게 해석 가능한 정보만 `meeting_slots`에 반영한다.
- 억지 추정보다 보수적 실패를 우선한다.
- 구조화가 불완전하거나 애매하면 `parse_warnings`에 이유를 남긴다.
- 시간 외 부가 텍스트가 섞여 있어도, 파싱 가능한 시간 정보가 있으면 그 부분만 구조화한다.

### 파서 수정 원칙

- 기존에 파싱되던 케이스를 깨지 않는다.
- 공통 규칙으로 처리 가능한 패턴은 최대한 일관되게 유지한다.
- 특정 학교에서만 나타나는 포맷은 학교별 parser에서 처리한다.
- 장소, 교수명, 비고 텍스트 때문에 시간 정보 추출이 망가지지 않게 우선순위를 둔다.
- 구조화 결과가 불확실하면 빈 `meeting_slots` 또는 부분 파싱 + warning이 잘못된 시간 생성보다 낫다.

### 기대 출력 계약

- 완전 파싱 가능:
  - `meeting_slots`를 채운다.
  - `parse_warnings`는 비운다.
- 부분 파싱 가능:
  - 확실한 slot만 `meeting_slots`에 반영한다.
  - 해석하지 못한 부분은 `parse_warnings`에 남긴다.
- 파싱 불가:
  - `meeting_slots=[]`
  - `lecture_time_raw`는 그대로 유지
  - 필요 시 `parse_warnings`에 파싱 불가 이유를 남긴다.

### 입력 패턴 분류

#### 1. 요일 + 시각 범위

예시:

- `목 12:00-13:15`
- `월 09:00-10:15 / 수 09:00-10:15`

기대:

- 요일과 시간 범위를 분리한다.
- 동일 문자열 안에 여러 세션이 있으면 각각 분리 처리한다.

주의:

- 구분자가 공백, 슬래시, 반복 요일 등으로 달라질 수 있다.
- 시각 기반 문자열을 교시 기반 구조에 매핑할 수 없으면 무리하게 period를 추정하지 않는다.

#### 2. 요일 + 시각 범위 + 장소

예시:

- `목 12:00-13:15 (벤처중소기업센터 10711)`
- `목 12:00-13:15 (벤처중소기업센터 10711-류재용) 목 13:30-14:45 (벤처중소기업센터 10711-류재용)`

기대:

- 시간 정보는 구조화 대상으로 본다.
- 괄호 안 텍스트는 우선 부가 정보로 취급한다.
- 같은 문자열에 여러 시간 범위가 있으면 각 범위를 별도 세션으로 취급한다.

주의:

- 괄호 안 `-`는 시간 범위가 아니라 강의실/교수명 구분자일 수 있다.
- 장소/교수명 텍스트 때문에 시간 토큰 분리가 깨지지 않도록 먼저 시간 패턴을 찾는다.

#### 3. 요일 + 교시

예시:

- `월 1,2교시`
- `화 3-4교시`

기대:

- 학교가 교시 기반 표현을 쓴다면 교시 정보를 `meeting_slots`로 구조화한다.
- 범위 표기와 열거 표기를 모두 고려한다.

주의:

- `3-4교시`가 3, 4 두 개의 slot인지 하나의 block인지 현재 모델 표현에 맞게 일관되게 처리한다.
- 교시 정의가 학교별로 다르면 공통 처리보다 학교별 처리를 우선한다.

#### 4. 복수 세션

예시:

- `월 09:00-10:15 수 09:00-10:15`
- `화 1,2교시 / 목 1,2교시`

기대:

- 한 문자열에서 여러 세션을 순서대로 추출한다.
- 세션 간 구분자가 일정하지 않아도 반복 패턴을 기준으로 분리한다.

주의:

- 단순 split으로 처리하지 말고, 요일/시간 패턴의 반복을 기준으로 분리하는 쪽이 안전하다.

#### 5. 온라인 / 미정 / 집중수업 / 비정형 텍스트

예시:

- `온라인`
- `미지정`
- `집중이수`
- `추후공지`

기대:

- 시간 구조화가 불가능하면 억지로 slot을 만들지 않는다.
- 원문은 보존하고 필요하면 warning을 남긴다.

주의:

- 의미 있는 수업 상태 정보일 수 있으므로 단순 폐기하지 않는다.

### 학교별 적용 원칙

- 공통 규칙으로 처리 가능한 범위만 공유하고, 문자열 특성이 크게 다르면 학교별 parser에서 처리한다.
- 특정 학교 전용 예외를 공통 로직에 넣을 때는 다른 학교 케이스를 망가뜨리지 않는지 먼저 확인한다.
- 새 학교를 추가할 때는 기존 학교 parser를 억지로 일반화하기보다 해당 학교의 대표 패턴을 먼저 문서와 테스트에 추가한다.

### 테스트 추가 기준

- 새 패턴을 지원하면 예제 입력과 기대 결과를 테스트에 추가한다.
- 파싱 실패 케이스도 테스트에 포함한다.
- 부분 파싱 케이스는 `meeting_slots`와 `parse_warnings`를 함께 검증한다.
- 특정 학교 이슈를 고쳤다면 그 학교 parser 테스트에 회귀 케이스를 추가한다.
- 장소/교수명/비고가 섞인 문자열은 반드시 하나 이상 테스트로 남긴다.

### 문서 갱신 기준

- 실제 운영 중 새로운 포맷을 발견하면 이 문서에 패턴을 추가한다.
- 파서의 허용 범위나 실패 정책이 바뀌면 문서와 테스트를 함께 갱신한다.
- 문서 예시는 가능한 한 실제 학교 응답과 가까운 형태로 유지한다.
